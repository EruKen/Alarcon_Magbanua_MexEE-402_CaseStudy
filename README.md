## What we learned

When we started Chapter 1, we assumed that data was already ready to use once we opened it. However, we learned that raw data is often messy, incomplete, inconsistent, or irrelevant, so it needs to be checked and cleaned before it can be used for machine learning. We also realized that data cleaning involves making decisions, not just following rules. For example, removing outliers such as the biggest sellers might also mean removing famous games, so we learned that we need to understand the data before deciding what to remove. With the help of AI, we were also able to fix errors and clarify some misunderstandings in Chapters 1 to 3.

In Chapter 4, about Transformation and Feature Engineering, we learned that we can create new and useful information from existing data. Techniques such as binning group numerical values into categories, interaction features combine variables, and polynomial features help represent non-linear relationships. We also learned that creating new features can help machine learning models understand patterns better. However, we realized that converting words into numbers requires care because the assigned numbers might create a meaning or order that does not actually exist in the data.

In Chapter 5, about Scaling and Normalization, we learned that computers process numerical values without understanding their actual meaning. Features with larger numerical ranges can affect certain machine learning algorithms more than features with smaller ranges. Through examples involving study hours and grades, we understood how scaling makes numerical features more comparable. We also learned that StandardScaler adjusts data to have a mean of 0 and a standard deviation of 1, while MinMaxScaler adjusts values to a range between 0 and 1. What we found interesting was that scaling does not remove the original information but changes the scale so that numerical features can be compared more fairly.

In Chapter 6, about Dealing with Outliers, we learned that outliers are data points that differ significantly from most values in a dataset. We explored different ways to detect them, including the Z-score method and the Interquartile Range (IQR) method. We also learned different ways to handle outliers, such as capping and flooring, log transformation, and removing extreme values when appropriate. One thing that surprised us was that different methods could give different results. For example, one method might not identify a value that clearly looks unusual, while another method might detect it. This taught us that no single method is perfect and that we should carefully examine outliers because they might be errors or important information.

In Chapter 7, about Feature Selection, we learned that having more features does not always mean having better results. Some features may not be useful for predicting the target variable and can make the analysis more complicated. We explored how correlation measures relationships between variables and how filter, wrapper, and embedded methods select relevant features in different ways. We also learned how Recursive Feature Elimination with Cross-Validation (RFECV) evaluates feature combinations and how Lasso regression reduces less useful feature coefficients to zero. What surprised us was that the three methods could select different features from the same dataset. We realized that we should not automatically consider one method's results as the final answer, especially when working with limited data.

In Chapter 8, we learned that a preprocessing pipeline works like a conveyor belt because it applies the same steps in the same order every time. Using the Titanic dataset, we practiced separating features from the target variable, handling missing values with SimpleImputer, and standardizing numerical features with StandardScaler. We also learned how Pipeline combines preprocessing steps and how ColumnTransformer applies specific transformations to selected columns, such as Age and Fare. We realized that the order of the steps matters because missing values need to be handled before scaling can be applied properly. What we found useful was that pipelines allow us to reuse the same preprocessing steps on new data, saving time and helping prevent mistakes.

Lastly, in the chapter about Real-World Application, we learned how the concepts from the previous chapters work together when preparing an actual dataset for analysis and machine learning. Using the Titanic dataset, we practiced handling missing values, scaling numerical features, encoding categorical variables, and creating new features such as AgeGroup and FamilySize. We also used Pipeline and ColumnTransformer to organize the preprocessing process. What we learned from this chapter is that data preprocessing is not something we do once and immediately consider finished. We still need to check our work and make sure that our results make sense. Creating charts helped us identify patterns in the data, but it also reminded us to check whether the labels and results were correct.

Overall, these chapters helped us understand that data preprocessing is an important part of machine learning because the quality of the data affects the results we can obtain. We learned how to clean data, create useful features, scale numerical values, handle outliers, select relevant features, and organize preprocessing steps through pipelines. Although we encountered errors and misunderstandings along the way, we were able to improve our understanding through practice and the help of AI. As we worked through the activities, we realized that data preprocessing is not only about using the correct tools or codes but also about understanding the data and making careful decisions before using it for machine learning.


## Errors we found
### Chapter 1-3 
  - In Chapter 1–3, there was an issue in the section on handling missing values in the Video Game Sales dataset. The following code was used to fill missing values in the Year and Publisher columns:

df['Year'].fillna(df['Year'].mean(), inplace=True)
df['Publisher'].fillna(df['Publisher'].mode()[0], inplace=True)

The code replaces missing values in the Year column with the mean (average) year and missing values in the Publisher column with the most frequently occurring publisher (mode). This helps prevent missing data from interfering with data analysis. However, these lines may produce a FutureWarning in newer versions of Pandas because of the use of inplace=True on a DataFrame column. To avoid this warning, the code can be changed to:

df['Year'] = df['Year'].fillna(df['Year'].mean())
df['Publisher'] = df['Publisher'].fillna(df['Publisher'].mode()[0])

The revised code assigns the results directly back to each column, making the operation more compatible with newer Pandas versions. After applying the changes, the missing values in both columns can be checked again using df.isnull().sum() to confirm that the imputation was successful. This improves data quality and prepares the dataset for the next preprocessing steps.


**Chapter 6: Dealing with Outliers**

**Error Code:**

```python
outliers = data[np.abs(z_scores) > 3]
```

**Corrected Code:**

```python
outliers = data[np.abs(z_scores) > 2]
```

The original code uses a Z-score threshold of 3, which identifies values more than three standard deviations from the mean. The corrected code uses a threshold of 2, making the outlier detection more sensitive and allowing more potential outliers to be identified. The threshold of 2 is appropriate if the objective is to detect values that are more than two standard deviations from the mean.

**Chapter 7: Feature Selection**

**Error Code:**

```python
selector = RFECV(estimator, step=1, cv=5)
```

**Corrected Code:**

```python
selector = RFECV(estimator, step=1, cv=3)
```

The original code uses five-fold cross-validation, while the corrected code uses three-fold cross-validation. The cv parameter determines how many folds the dataset is divided into during model evaluation. Changing it from 5 to 3 reduces the number of folds and changes how the model evaluates the selected features. This correction is valid if three-fold cross-validation is the intended setting for the activity.
